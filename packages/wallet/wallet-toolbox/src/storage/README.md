# WalletStorage

Provides access to persistent storage in support of Wallet.interfaces.

This includes:

- Direct storage on a variety of databases.
- Remoted storage to service providers for backup and mobile support.
- Synchronization between multiple stores.
- Import from legacy stores.
- Support single user, multi-read/single write, full multi-user modes.

## Failed Transaction Output Handling

When a transaction is marked `failed`, storage must repair both sides of the optimistic
UTXO state created while the action was being built:

- Inputs selected by that transaction are released by clearing `spentBy` and setting
  `spendable` back to `true`.
- Outputs generated by that same failed transaction are made inert by clearing `spentBy`
  and setting `spendable` to `false`.

This distinction matters because created output rows can exist before a transaction is
signed, broadcast, or proven. If a later construction, review, or delayed-send step fails,
those rows must remain as history only; they must not be treated as funding candidates or
left as phantom UTXOs in raw storage accounting. `reviewStatus` repeats the same repair for
legacy rows and only restores inputs or neutralizes generated outputs when the failed
transaction has no active ProvenTxReq that could still reconcile.
