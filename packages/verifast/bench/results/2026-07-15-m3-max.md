# VeriFast benchmark — 2026-07-15

This is an end-to-end comparison of `Transaction.verify('scripts only')` using
the SDK `Spend` interpreter and the bundled BDK WASM verifier. Timings include EF
serialization, the WASM boundary, BDK parsing, and transaction bookkeeping.
Module initialization and one JIT warmup call were excluded.

## Environment

- MacBook Pro, Apple M3 Max, 128 GB RAM
- macOS 26.5.1 (25F80), arm64
- Node v25.9.0, pnpm 10.33.2
- Google Chrome 150.0.7871.116, headless
- `bdk-core.mjs` SHA-256: `96bbdb87124814a0cdafa3388139ce3fb31e5e63bab87b849f4e69b19297f12e`
- `bdk-core.wasm` SHA-256: `e9158fe25c833d5fab87df80602e464a1ac675bb8656a6b1226bbdc171fac9f0`

## Interpretation

On this machine and corpus, the BDK and SDK P2PKH paths are effectively at
parity. BDK is about 1% faster at the largest Node vector and 0–1% faster in
Chrome; the pure SDK path is faster for trivial non-signature scripts because
the fixed EF/WASM/parse overhead dominates. The useful result of this baseline
is correctness and deployability, not a claim of a universal WASM speedup.
