# Identity and credential migration

This release removes Simple's mutable transaction-based DID adapter and signature-looking VC/VP wrappers. Upgrade integrations together; retain existing wallet/certificate storage and historical chain records. No production data deletion, automatic migration transaction, service installation, or reissuance is performed.

| Previous API                                                                           | Replacement                                                                                                                                                                          |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `DID.fromIdentityKey(key)` returned a legacy document                                  | Returns the canonical BRC-202 `did:key` string; use `DID.resolve(did).didDocument`                                                                                                   |
| `wallet.getDID()` returned a legacy document                                           | Returns the BRC-202 Multikey document                                                                                                                                                |
| `wallet.resolveDID(did)` used remote/chain providers                                   | Synchronous offline `DidResolutionResult` for the identity-key subset                                                                                                                |
| `DID.parse`, `isValid`, `fromTxid`, `buildDocument`, certificate-type helpers          | Strict identity-key encode/resolve; no transaction/serial identity fabrication                                                                                                       |
| `createDID`, `updateDID`, `deactivateDID`, `listDIDs`, `registerDID`                   | Removed: immutable profile has no mutable lifecycle or registration                                                                                                                  |
| DID resolver/proxy configuration and `DIDResolverService` / `createDIDResolverHandler` | Removed: no remote resolver is needed for this profile                                                                                                                               |
| `toVerifiableCredential` and copied proof metadata                                     | `exportBRC52Envelope(originalBinary)` or verified structured-core exporter from `@bsv/did/brc52`                                                                                     |
| `toVerifiablePresentation` / `wallet.createPresentation`                               | Removed: use explicit BRC-100/BRC-103 disclosure and verifier keyring flows; no replacement holder proof is fabricated                                                               |
| `issuer.issue(...)` returned an old wrapper                                            | `{ credential: BRC52Envelope, keyringForSubject }`; keep keyring delivery separate                                                                                                   |
| `issuer.verify(vc)` returned `valid` / inferred `revoked`                              | `issuer.verify(JSON.stringify(envelope))` returns `verified` and `verifiedDocument`; evaluate trust/status separately                                                                |
| HTTP verify accepted `{ credential: parsedEnvelope }`                                  | Send `{ credential: originalEnvelopeJson }`; the string is verified verbatim. Object credentials are rejected; use strict UTF-8/request JSON decoding for custom framework adapters. |
| `issuer.isRevoked(serial)` used local secret absence                                   | `getRevocationRecordStatus(serial)` supplies local retained/unknown only; chain status needs explicit evidence                                                                       |
| `wallet.acquireCredential` / `listCredentials` returned wrappers                       | Return authenticated BRC-203 envelopes                                                                                                                                               |

Before, wrapper consumers read `vc._bsv.certificate` and `vc.proof.signatureValue`. After, they keep original binary in `envelope.certificateBinary`, verify with `verifyBRC52Envelope('application/json', input)`, and consume only `result.verifiedDocument`. Do not add timestamps, schema names, plaintext, or status claims to that closed graph. Keep UI metadata separately attributed.

A historical transaction DID or serial overlay result has no automatic identity-key mapping. Recover independently authenticated issuer/subject identity-key bindings and original signed certificate bytes. Historical short certificate types or serialization that cannot reproduce the original signed preimage require an explicit recovery/migration decision; the bridge rejects them rather than silently padding, reordering, or re-signing. Preserve originals for audit and rollback.

Applications that require a stable mutable identifier need a separately specified continuity method. Renaming the old DID to `did:key` cannot preserve rotation/recovery semantics. A different key creates a different DID and needs contact updates and certificate reissuance where applicable. Roll back to the previous package only with its documented trust limitations; forward-fix applications using authenticated original data and the new explicit APIs.
