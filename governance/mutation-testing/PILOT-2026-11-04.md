# Mutation efficiency pilot

Diagnostic experiment. Measurements and acceptance state are recorded in
[PR #1495](https://github.com/bsv-blockchain/ts-stack/pull/1495). This mechanism
grants no publication qualification.

The pilot tests focused regression files before composed property files. The
existing stop-on-kill environment already skips remaining assertions after the
first failure for an active mutant. The candidate changes file order only;
unmutated runs and surviving mutants retain every selected test. No production
runtime code, canonical mutation range, score floor, coverage gate, 300-case
property count, seed 3242026, native fixture, concurrency, worker recycling, or
per-mutant deadline changes.

Dispatch the existing **Mutation quality** workflow on the reviewed branch with
`target=efficiency-pilot`. Three ubuntu-22.04 jobs run at most concurrently;
each job runs the original ordering followed by the candidate on the same
runner, with the same source, frozen dependencies and exact-run build archive.
Each job is capped at 240 minutes (12 aggregate runner-job hours maximum, plus
one build); each local Stryker child is also capped at 180 minutes. Failed and
partial samples remain artifacts. Do not retry automatically or launch the full
606-part campaign as part of this experiment.

| Case                          | Selected canonical execution parts | Scope                                                         |
| ----------------------------- | ---------------------------------- | ------------------------------------------------------------- |
| private-purchase-native-clock | progress-8                         | 109-site historical stress part, not the whole 68-part target |
| private-purchase-disclosure   | auto-3                             | 197-site historical stress part, not the whole target         |
| private-lookup-buyer          | buyer, payment                     | Entire target; known score/coverage failures remain visible   |

Counts above describe the historical baseline and are checked against the pinned
engine's actual inventory for this source before accepting a pilot report. The
lookup buyer's declared property file was absent from its test selector; this
pilot adds it to **both** arms. That narrow correction was independently merged
through [PR #1497](https://github.com/bsv-blockchain/ts-stack/pull/1497); this
does not adopt PR #1478's other changes.
Historical timings from different hardware/contention are context, not an A/B
speedup denominator.

`scripts/mutation-pilot.mjs` compares source, configuration (allowing only the
sequencer and report destination), every canonical mutation tuple, every test's
source/name/location, and runtime identity. It rejects lost kills, newly
uncovered sites, invalid results, new timeouts, and unexecuted survivors. Existing
survivors and policy failures remain in the result. Future dispatches expose baseline artifacts before the candidate starts and stream
Stryker phase/progress output. The process group deadline also stops owned child
workers. Raw Stryker reports, logs,
digests, elapsed times and comparison JSON are retained for 30 days.

This workflow issues no qualification receipt or qualified source output.
A successful diagnostic comparison is not a passing score or publication
qualification. Qualification and release workflows keep their original complete
canonical union and fail-closed verifier. Promotion of ordering into ordinary
campaigns requires all three controlled comparisons and an exact-head green PR.
Evidence reuse, incremental mutation state, affected PR selection, and replacing
serial 256-part batch barriers require separate invalidation/shadow proofs;
none is silently trusted by this pilot.

Local phase profiling on macOS (Node 24.22.1, one Jest process) passed the same
447 native-clock tests in both arms: 270.830 seconds original, 293.442 seconds
candidate. Four expensive alias properties consumed about 84% of the original
run. This identifies an ordering opportunity for killed mutants; it does not
establish a mutation speedup. This phase profile is not used as the controlled
measurement denominator.

## First controlled result

[Run 41939120625](https://github.com/bsv-blockchain/ts-stack/actions/runs/41939120625)
uses source `923cdb71e2a02e0111104b0096122c02b364574b` in both arms.
Disclosure `auto-3` finished at 01:43:43 UTC on November 5: **2965.410 seconds
original versus 2623.521 seconds candidate**, a **1.1303× speedup / 11.53% wall
reduction**. All 197 identities matched: 171 killed and 26 survived in both
arms, with no timeout, uncovered, invalid, unexecuted or harness-limit kills.
The raw initial runner executed 134 tests in both arms; its report serializes
126 test definitions because parameterizations can share a Jest full-name ID.
The comparison checks both counts separately, plus definition identities and
the actual declared property source. Artifact `13380442262` ZIP SHA256:
`7ecb1582c97c3fee47cbcb0dbcf4fe899c28b7d825bb512a824c2849588459e9`.

This is a modest speedup for a partial target, not complete-target qualification
or proof of a repository-wide reduction. Whole buyer remains pending; native-clock was rejected as described below. Disclosure survivor durations account for about 89% of candidate
mutant execution time (summed mutant elapsed time, not CPU billing). An
independent unchanged 300-case local phase profile passed all 134 tests in
279.919 seconds, with roughly 80% of sampled stacks inside the native protected
ledger. Changing file order cannot remove this real work for survivors. Do not
cache mutable fixtures or authorization/validation verdicts, reduce property
exploration, or raise limits to make this experiment appear faster.

A necessary configuration regression check covers the 150 explicit Jest target
selectors and rejects the previously omitted buyer property. It does not infer
package defaults, Vitest selection or ignore-pattern behavior. The actual raw
report must also contain the declared property's source and test definitions.

Property exploration interrupted by its time limit is distinct from an
assertion counterexample. The historical native-clock stress report records 13
of its 97 reported kills this way, after only 246–293 of 300 cases. Raw statuses
and policy metrics stay unchanged; the pilot flags these observations and Jest test/hook deadlines reported as kills for
independent adjudication and cannot accept them silently as preserved assertion
detection. The shared guard described below now rejects this incomplete evidence; no
qualification result is granted.

## Native-clock comparison rejected

The same original run finished `progress-8` in **4477.635 seconds original
versus 3954.212 seconds candidate** (11.69% less wall time). All 109 sites and
447 initial tests matched, but the comparison failed: one reported kill became
a survivor and two survivors became reported kills. Each changed kill was a
property interruption, not a recorded assertion counterexample: original site
102 interrupted after 290/300 cases; candidate sites109/110 after284/297.
The original arm has35 and candidate22 interrupted kills across37 distinct
sites, caused by the unchanged alias disclosure/coordinator properties.

The raw 107/108 kill totals and98.165/99.083% scores are preserved. This result
is **not accepted** as detection-preserving speedup or qualification. These
observations do not establish equivalence or distinguish resource contention
from actual mutated performance defects. Ordering remains pilot-only; neither
higher limits nor fewer property cases are an acceptable proof. Artifact
`13383365578` ZIP SHA256:
`19408892e06552cdd58f2163e33010e14cb9b4fe5c7792ebd58409dfdbdb80db`.

## Qualification guard after the rejected sample

`mutationRunnerLimit` classifies property interruptions and Jest test/hook
limits reported as Killed. `calculateMutationMetrics` retains the original raw
counts, denominator and score and adds a separate `runnerLimitedKills` count.
Ordinary execution, per-part evidence and the final independent canonical raw
recheck all use the same evaluator and reject a nonzero count, even for a part
whose global score is checked later. A matching digest or a forged passing
receipt cannot turn the incomplete raw report into qualification. Explicit
Stryker Timeout semantics remain unchanged. There is no override or allowance
for runner-limited kills. This strengthens the evidence gate; it does not
promote the rejected ordering experiment.
